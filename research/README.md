# Research archive

The library, examples, correctness checks and maintained benchmarks live in the
current tree. Historical experiments and raw measurements are preserved together
in the public tag **`archive/research-2026-09-24`**, at commit
**`00f96248cc404e2d662d9e51c457d811701fa889`**:

- [Browse the frozen snapshot](https://github.com/bgtnt/polylinekit/tree/00f96248cc404e2d662d9e51c457d811701fa889).
- [Download its source ZIP](https://github.com/bgtnt/polylinekit/archive/00f96248cc404e2d662d9e51c457d811701fa889.zip).
- [Inspect the file and checksum manifest](archive-manifest.json).

This is a research snapshot, not a library release. It contains all 377 tracked
files from that commit (36,675,389 bytes), including the original `results/`,
`experiments/`, recognition consumer, protocols, scripts and notices. Original
relative paths remain intact. It does not include ignored local builds or
downloaded datasets. Library users do not need to download this archive.

The recognition evaluation did not justify further development of an area-based
recognizer. RMS was the inexpensive gesture default under the evaluated policy;
DTW had the highest held-out digit accuracy among the tested methods. A modest
digit-combination improvement did not establish area as a general recognition
metric. These findings and their limitations remain public; archiving them does
not change the conclusion.

## Reproduction

For a separate checkout retaining Git history and the original relative paths:

```sh
git clone --branch archive/research-2026-09-24 https://github.com/bgtnt/polylinekit.git polylinekit-research
cd polylinekit-research
git rev-parse HEAD
```

The last command must print the full commit above. Follow each archived report's
commands and environment requirements from that checkout. Some comparisons build
earlier commits, so they require Git history rather than just the ZIP. Recognition
replay requires the documented dataset import; original coordinates are not
redistributed. Historical timing is machine-specific and is not regenerated by
building the current library.

The manifest records each file's path, byte length, Git blob ID and SHA-256 of its
**Git blob bytes**. ZIP entries preserve those bytes. A checked-out working tree
can have different line endings, so verify the ZIP or `git show` bytes rather than
assuming filesystem hashes match. The published ZIP was independently checked
against all 377 manifest entries before removing the old paths from the current tree.

The current [benchmark guide](../benchmarks/README.md) maintains runnable geometry
workloads and one exact synthetic fixture from this snapshot. New output goes
under ignored `artifacts/`; the [current performance assessment](../docs/performance.md)
links to the frozen evidence instead of committing duplicate run output.

Git history and the public archive remain available. This layout reduces the
current source tree and browsing clutter; it does not erase or shrink historical
Git objects.
