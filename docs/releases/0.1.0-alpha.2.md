# PolylineKit 0.1.0-alpha.2

**Status: available as a [GitHub prerelease](https://github.com/bgtnt/polylinekit/releases/tag/v0.1.0-alpha.2).
NuGet.org publication is pending.** The latest NuGet version is still
[0.1.0-alpha.1](0.1.0-alpha.1.md). Download the original alpha.2 packages from
the release and follow the [package installation guide](../releasing.md#install-alpha2-from-github).

This update improves polygon input and the package quick start. It adds no area
algorithms, optimization or new runtime dependencies to Core. No new speed claim
is made for alpha.2.

## Changes

- Package READMEs lead with installation and a small usage example. Installation
  uses `--prerelease`, and package metadata includes IoU and overlap search terms.
  Package verification checks the actual embedded README and nuspec to prevent
  outdated release-process wording or a mismatched version being shipped again.
- `PreparedRegion.FromPolygon(exterior, holes)` and `FromPolygons(polygons)`
  preserve explicit exterior/hole roles by orienting copied rings. The guide
  explains the raw `FromRings` result of 100 versus 84 for a same-direction hole.
- The [NetTopologySuite interoperability example](../../examples/NetTopologySuiteInterop/README.md)
  converts valid Polygon/MultiPolygon input without adding a dependency to Core.
  It checks the complete county/district fixtures and records NTS behavior on
  selected invalid rings. The [correctness report](../../examples/NetTopologySuiteInterop/RESULTS.md)
  records the actual largest observed differences and NTS outcomes; it takes no new timings.
- The quick start distinguishes numeric area metrics, output contour operations
  and a general geometry model, with scoped historical comparisons and losses.

## Compatibility and decisions

This is an additive API update. Assembly identities remain
`PolylineKit.Winding.dll` for Core and `PolylineKit.dll` for the Clipper adapter;
public types retain the `PolylineKit` namespace. No existing methods are removed.
The `WindingArea` convenience methods remain available for compiled consumers;
the duplicate `FilledArea` and `IntersectionArea` methods are marked
`EditorBrowsable(Never)` to reduce IntelliSense duplication. New code should use
`PolylineArea` for single walks and `RegionArea` for regions.

`FromRings` still copies supplied directions without assigning shell/hole roles.
All existing default fill rules remain `NonZero`. There is no new NTS adapter
package, and alpha.1 is not rebuilt, replaced or unlisted by these changes.
Assembly renaming, method removal and any later unlisting remain owner decisions.

## Input and numerical limits

The role-based factories reverse exteriors with negative signed area and holes
with positive signed area. Exactly zero-signed-area rings are stored as supplied.
For valid simple polygon boundaries, NonZero and EvenOdd describe the same
polygon. For several valid polygon parts, NonZero gives their union while EvenOdd
fills points covered by an odd number of parts; a two-part overlap cancels.
Invalid self-intersecting boundaries do not
gain a topology guarantee from signed-area orientation.

Coordinates remain planar and unchanged in position and scale. No factory infers
nesting, repairs geometry, projects coordinates or inserts edges between parts.
Calculations use `double`; exact geometric predicates do not make crossing
positions or areas exact. See the [region contract](../regions.md) and
[memory behavior](../performance.md#first-use-and-retained-workspace).

## Validation and delivery

Windows Release build completed with zero warnings and errors. Five-mode
verification passed: **183,604** checks with the portable assembly and **183,532**
in each modern mode (normal, forced scalar, no AVX and no hardware intrinsics).
Prepared-region checks passed with modern, forced scalar and portable assemblies:
**5,919** prepared-input assertions and **5,600** full GIS comparisons per mode,
alongside the existing analytic, partition and grouping checks. The unchanged
precompiled legacy consumer passed **41** checks on each library target pair.

The NTS example passed **62** conversion contracts, **12** analytic invalid-walk
controls and **45,028** full GIS metric checks on 1,400 pairs in both directions
and fill rules. Maximum own-area difference was `3.814697265625e-5` m²,
intersection difference `6.9141387939453125e-6` m² and IoU difference
`9.43689570931383e-16`. These are comparisons with the configured NTS overlay,
not exact-area error bounds. No tolerance was loosened. The README/nuspec guard
passed **21** positive/rejection controls.

Four fresh PackageReference consumers passed on .NET 8 and .NET 10: Core-only
and optional Clipper, each against its actual package target. All exercised the
new factories and four direction combinations, as well as the existing coverage,
empty-region, transform and adapter contracts. Core-only restore contains no
third-party packages. The actual packaged READMEs passed metadata/text inspection.
Consumer restore used isolated caches with the produced feed and the already
cached Clipper2 archive; no new package versions were downloaded.
