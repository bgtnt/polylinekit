# PolylineKit 0.1.0-alpha.3

**Status: release preparation.** This version delivers the guarded polygon
orientation optimization already checked in `main`. The package pair will be
verified from a clean source commit before delivery; alpha.2 remains unchanged.

## Changes

- `PreparedRegion.FromPolygon` and `FromPolygons` orient well-conditioned copied
  rings with a compensated signed-area sum around a local origin. This avoids
  another ring copy and full winding evaluation. Tiny, cancelling or uncertain
  sums retain the previous orientation route after the preliminary pass.
- The interactive contour simplification example has automated browser checks
  for nonmonotone candidate errors, inclusive budgets, stale responses and
  exporting the selected candidate. Entering `0.7%` now produces the same
  fraction as the initial budget, avoiding a one-ULP exclusion at the inclusive
  boundary. Its browser tooling is test-only.
- A reusable delivery check compares NuGet.org downloads with the original
  verified package entries and runs fresh package-only consumers on .NET 8 and
  .NET 10.

There is no public API, assembly-name, target-framework, default fill-rule or
runtime dependency change. Core still has no third-party runtime packages. The
optional adapter still depends on Core and Clipper2. The intersection engine is
unchanged; the example's Clipper simplifier is not a new Core algorithm.

## Evidence and limits

The [preparation report](../../benchmarks/PolylineKit.PreparationBenchmarks/RESULTS.md)
compares the actual alpha.2 binary with source `a7cad8a`: the complete 114-region
Census construction batch was 4.13× faster with 46.4% fewer managed bytes.
These are measurements of that source and workload, not new timings of the
alpha.3 package. The smaller 7–8.5% end-to-end median differences have substantial
process variation. Reversal and uncertain-sign fallback were not exercised in
the timed inputs, so universal acceleration is not promised.

The [Helsinki assessment](../../benchmarks/PolylineKit.IndependentRegions/RESULTS.md)
still checks the actual published **alpha.2**, not alpha.3. It records Core/NTS
agreement and the failed three-way gate; it adds no performance result.
This release does not turn that historical assessment into an alpha.3 check.

Exact geometric predicates do not make intersection positions or final areas
exact. Signed-area orientation does not repair invalid polygon topology. See
the [region contract](../regions.md) and [performance limits](../performance.md).
