# PolylineKit 0.1.0-alpha.1

**Status: alpha candidate prepared locally; not published on NuGet.org.**
The candidate provides numeric area and region overlap for .NET, with a
dependency-free core and an optional Clipper2 adapter for quantized comparisons
and output contours. There is no new claim of speed for these package binaries.

## Choose a package

| Package | Use | Assemblies and dependencies |
|---|---|---|
| `PolylineKit.Core` | Filled area, intersection, region comparison, normalization, sampling and alignment | `PolylineKit.Winding.dll`; no external runtime libraries |
| `PolylineKit.Clipper` | Existing decimal-grid comparisons and resolved output contours | `PolylineKit.dll`; Core and Clipper2 2.0.0 |

Both packages contain `netstandard2.0` and `net10.0` assemblies, XML API
documentation, their own README, the MIT license and repository metadata.
The package IDs describe their roles; historical assembly identities are
preserved for binary compatibility. Public types remain in `PolylineKit`.
Deploy the resolved dependency graph, not an isolated replacement DLL.

Follow the [local-feed instructions](../releasing.md) and run the
[coverage example](../../examples/PackageCoverage). Its nonconvex L-shaped zone
has area 20, the footprint has area 16, and their intersection is 7. Coverage is
35%; union is 29 and IoU is 7/29. The zone's area is cached, and zero-area zones
have undefined coverage. This is an analytic usage check, not a timing result.

## Delivery verification

`scripts/verify-packages.ps1` packs Release binaries from a committed checkout,
inspects both actual `.nupkg` files, and restores four consumers outside the
repository, using only `PackageReference`:

| Consumer | Selected library assets | Contract |
|---|---|---|
| Core / .NET 10 | `net10.0` | Coverage, region comparison and transformation; no adapter or Clipper |
| Core / .NET 8 | `netstandard2.0` | Same Core contracts |
| Clipper / .NET 10 | `net10.0` | Core types plus quantized comparison and output contours |
| Clipper / .NET 8 | `netstandard2.0` | Same adapter contracts |

The verifier isolates NuGet caches and maps `PolylineKit.*` to the produced
local feed. It checks `project.assets.json`, restored package bytes, selected
assembly target attributes and runtime references. Running portable assets under
.NET 8 is not a .NET Framework test. CI repeats the package check on Windows
and Linux, alongside the existing correctness and legacy-consumer checks.

The generated `verification.json` records the exact source commit, package
SHA-256 values and consumer outcomes. It accompanies the local package pair;
publishing a different rebuild requires a fresh verification record.

only to qualifying integer inputs for one filled area. None of these results
establishes a universal ranking or a speed promise for the alpha candidate.

## Limits and evaluation scope

- Coordinates are planar. There is no geographic projection or geodesic area.
- Each operand is one ordered walk, closed implicitly. This is not a general
  rings/holes/multipolygon collection API. Self-intersections follow the chosen
  NonZero or EvenOdd fill rule.
- `double` areas and intersection coordinates can lose precision, even when
  geometric predicates are exact. Read the [input and numerical contract](../area.md).
- Overlapping footprints' individual coverages cannot simply be added to obtain
  union coverage. A trusted simple ring's own area is cheaply computed by shoelace.
- The 4 MiB retained-array limit is per engine per thread, not a peak-memory
  cap. Large repeated inputs can allocate again. See [memory behavior](../performance.md).
- The adapter quantizes coordinates and uses Clipper2 even when contours are
  not requested. Core area calls do not load it.

## After alpha

Evaluate one independent source of real nonconvex regions beyond Census.
Fix data selection, eligible inputs, common cheap rejection checks, requested
outputs and comparator preparation before measuring. Preserve original
coordinates; do not modify them to trigger integer specialization. Publish
unsuccessful cases too. This bounded portability study is a follow-up, not a
prerequisite for evaluating the working alpha packages.
